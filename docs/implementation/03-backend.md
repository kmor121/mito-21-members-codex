# バックエンド関数 実装ガイド

> Phase 5で順次記載予定。

## 共通設計方針

- **AI不使用**: すべてのバックエンド関数は非AI処理のみ。外部API呼び出しに限定。
- **シークレット管理**: APIキー（Resend APIキー等）はBase44のシークレット機能で管理。コードにハードコーディングしない。Eliteプラン移行時にシークレットの再設定が必要。
- **エラーハンドリング**: API呼び出し失敗時はエラーログを残し、ユーザーにわかりやすいメッセージを返す。リトライは行わない（冪等性を保証できない場合）。
- **クレジット消費禁止**: Base44内蔵AI・内蔵メール・スケジュールタスクは一切使用しない。

## 関数一覧

### 1. sendApplicationNotification — 入会申込メール通知

| 項目 | 内容 |
|------|------|
| トリガー | P1（入会申込フォーム）送信時 |
| 処理概要 | 1. 管理者宛に「新規入会申込あり」の通知メールを送信 2. 申込者宛に「受付完了」メールを送信 |
| 使用API | Resend API（POST /emails） |
| 使用シークレット | RESEND_API_KEY |
| 入力 | 申込者のメールアドレス、氏名、管理者メールアドレス |
| 出力 | 送信成功/失敗ステータス |

### 2. sendApprovalEmail — 承認・却下メール送信

| 項目 | 内容 |
|------|------|
| トリガー | A4（入会申込管理）で承認または却下操作時 |
| 処理概要 | 承認時: ウェルカムメール送信。却下時: 却下理由を含む通知メール送信 |
| 使用API | Resend API（POST /emails） |
| 使用シークレット | RESEND_API_KEY |
| 入力 | 対象会員のメールアドレス、氏名、承認/却下ステータス、却下理由（却下時） |
| 出力 | 送信成功/失敗ステータス |

### 3. sendNewsletter — メルマガ配信

| 項目 | 内容 |
|------|------|
| トリガー | A7（配信管理）で送信操作時 |
| 処理概要 | 1. セグメント条件に基づき対象会員のメールアドレスを取得 2. Resend APIで一括送信（即時 or send_atで予約） 3. Newslettersのステータスを更新 |
| 使用API | Resend API（POST /emails、send_atパラメータ対応） |
| 使用シークレット | RESEND_API_KEY |
| 入力 | Newsletter ID、送信タイプ（即時/予約）、予約日時（予約時） |
| 出力 | 送信成功/失敗ステータス、送信件数 |
| 備考 | 予約送信はResend APIの`send_at`パラメータに全面依存。Base44側にスケジューラは不要 |

### 4. sendDueReminder — 会費リマインド配信

| 項目 | 内容 |
|------|------|
| トリガー | A5（会費管理）でリマインド送信操作時 |
| 処理概要 | 1. 当年度の未納会員一覧を取得 2. リマインドメールを一括送信 |
| 使用API | Resend API（POST /emails） |
| 使用シークレット | RESEND_API_KEY |
| 入力 | 年度ID |
| 出力 | 送信成功/失敗ステータス、送信件数 |

### 5. executeFiscalYearTransition — 年度切替処理

| 項目 | 内容 |
|------|------|
| トリガー | A8（年度管理）で年度切替実行操作時 |
| 処理概要 | 1. Organizationsを新年度用にコピー（任意） 2. DueSettingsに基づきDuesを一括生成（status=活動中の正会員・賛助会員のみ） 3. 前年度のis_new=trueの会員をfalseにリセット 4. 前年度のis_currentをfalse、新年度をtrueに切替 |
| 使用API | なし（Base44内部のコレクション操作のみ） |
| 使用シークレット | なし |
| 入力 | 新年度ID、組織コピー有無フラグ |
| 出力 | 処理結果（生成されたDues件数、リセットされた会員数等） |
| 備考 | AI機能不使用。コレクションのCRUD操作のみで完結 |
